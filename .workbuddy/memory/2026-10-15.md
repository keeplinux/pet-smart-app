## 修复切模式回来涂色丢失（真根因：StrictMode 双挂载，v1.3.10）

v1.3.9 的 effect 顺序修复无效——用户复测依旧涂色消失。**真根因**：main.tsx 用了
`<StrictMode>`，开发模式组件「挂载→立即卸载→重新挂载」：批次 1 创建场景 A 并把
faceStateRef 标为 true、动画任务指向 A；cleanup 销毁 A；批次 2 创建全新场景 B——
**refs 跨双挂载保留**，faceStateRef 已是 true → 联动 effect 差异对比 continue 跳过
→ 场景 B 无人上色，永久 ghost。
- **修复**：初始状态不依赖跨挂载 ref 记忆——init effect 创建模型后**按 filledViewsRef
  定格上色**（color/opacity/transparent/depthWrite 直设 + wire.visible=false）并同步
  faceState + 清空 animsRef；增量变化（新拍照）仍走联动 effect 的 300ms 渐入动画。
  无论双挂载批次跑几次，状态总以数据（views 照片）为准重建。
- 新增 filledViewsRef（ref 同步 effect 里更新），init 读 ref 不进依赖（exhaustive-deps）。
- **教训**：①StrictMode 双挂载下 useRef 状态跨批次残留，画布类组件的初始状态必须在
  init effect 里按 props/数据重建；②上一轮"effect 声明顺序"修复方向对但只治了
  facesRef null 时序，没治 faceState 残留——根因假设要验证到底。
- 版本：package.json 1.3.10；build.gradle versionCode 27 / versionName "1.3.10"。

## 修复画布重挂载后涂色丢失（v1.3.9）

用户反馈：四视图上传后涂色正常，但重新点「四视图照片」（模式切换）后涂色消失，
照片其实还在。**根因**：模式切换 → CaptureStage 卸载重挂载 → React 同组件 effect
按声明序执行，filledViews 联动 effect 声明在场景初始化 effect **之前**——挂载时先跑，
此刻 facesRef 还是 null → return，上色任务丢失；之后无新状态变化再触发 → 模型永久
保持 ghost 态（faceStateRef 也随重挂载重置为全 false，但照片在 views 里没变）。
- **修复**：filledViews effect 挪到初始化 effect 之后声明（挂载时先建模型再联动上色），
  注释写明顺序约束。修复后：切模式回来，已拍照片对应面立即恢复上色动画。
- 核心教训：**"组件内 effect 声明顺序 = 执行顺序"，跨 effect 的 ref 依赖必须让生产方
  声明在消费方之前**。
- 版本：package.json 1.3.9；build.gradle versionCode 26 / versionName "1.3.9"。

## 修复左右扇区映射反了（v1.3.8）

用户反馈：右侧视图时还没传照片模型右侧已上色。**根因**：SphereGeometry 经度映射
φ=0→-X、π/2→+Z、**π→+X**——猫左侧是 -X（中心 φ=0）、右侧是 +X（中心 φ=π），
v1.3.7 把 left 划在 φ=π、right 划在 φ=2π（标反）。拍左侧实际点亮右半区，转身到
右侧视图时正对已上色扇区 → "没拍就上色"。
- **修复**：扇区中心对准各面、边界落 45° 斜角——front φ∈[π/4,3π/4]、left
  φ∈[-π/4,π/4]（负 phiStart 跨零点，three 的 cos/sin 支持负角）、back
  φ∈[-3π/4,-π/4]、right φ∈[3π/4,5π/4]，边界闭环无缝。
- 验证链：左侧视图姿态 rotation.y=π/2 时本体 -X（left 扇区中心）朝相机 ✓ 拍左侧
  → 相机所见面点亮 ✓。
- 版本：package.json 1.3.8；build.gradle versionCode 25 / versionName "1.3.8"。

## 首页星球拖动改为「直接操纵」手感（v1.1.2）

用户反馈：星球滑动时模型移动方向与滑动方向不一致（反人类）。根因：之前用 OrbitControls
转**相机**（绕世界 Y/极角轴），45° 斜俯视下水平拖动时球面内容沿斜弧移动，观感方向错乱。

### 重构（HomeScene.tsx）
- **转球不转相机**：星空改背景幕（scene 直属，不随拖动）；planet + contentGroup 装进
  `planetGroup` 可旋转组。拖动时 `rotateOnWorldAxis(camUp, dx·k)` + `rotateOnWorldAxis(camRight, dy·k)`
  ——旋转轴取**屏幕竖直/水平轴**（相机 right/up 世界向量），内容移动方向与手指滑动方向严格对齐，
  无斜向漂移。
- **OrbitControls 降级为仅缩放**：`enableRotate = false`（保留双指捏合/滚轮 dolly + min/maxDistance
  + damping）。构造时它已设 `touch-action: none`，单指拖星球不会触发页面滚动。
- **自写拖拽**：pointerdown（isPrimary 才启动，第二根手指让给 OrbitControls 做 dolly）/
  pointermove（旋转 + 平滑记录惯性角速度）/ pointerup（保存姿态）。setPointerCapture 防拖出丢事件。
- **惯性滑行**：松手后渲染循环 `rotatePlanet(inertia)`，每帧 ×0.92 衰减，真实转球手感。
- **灵敏度**：`PLANET_DRAG_SPEED = 0.35`，k = 2π·0.35/clientHeight（拖满屏高约转 126°）。
- **视角记忆扩展**：saveView 存 `{camera, planet: quaternion}`；恢复时相机位置 + 星球姿态一起还原
  （用户上次转到面前的设备，下次打开还在面前）。旧格式 {x,y,z} 兼容读取。
- 点击拾取（<6px 阈值）不受影响；猫/设备随组旋转（raycast 世界矩阵自动正确）。
